Compositeur de projet — Méthode de calcul

Rapport autonome destiné au développeur. Il définit uniquement la logique de calcul du Compositeur : surfaces intérieures / extérieures, prestations 3D, prestations 2D, prix horaire, prix fixe et pourcentage. Cette logique doit être unique et identique entre Frontend, API, base de données, devis et PDF.
Périmètre : Compositeur uniquement Calcul temps réel Admin = source de vérité Responsive PC / tablette / mobile
Règle fondamentale

1. Ne jamais appliquer une seule surface globale à toutes les prestations

Le Compositeur doit maintenir séparément :

surfaceInterior
surfaceExterior

La surface intérieure correspond à la somme des niveaux intérieurs réellement traités :

surfaceInterior =
R-2 + R-1 + RDC + R+1 + R+2 + ...

La surface extérieure correspond à la surface extérieure réellement traitée : terrasse, jardin, piscine, cour, parking ou autre zone extérieure selon le projet.

Interdiction : ne jamais utiliser automatiquement surfaceInterior + surfaceExterior comme quantité pour tous les services. Chaque prestation doit connaître son propre périmètre et son propre mode de calcul.
3D · INTÉRIEUR / EXTÉRIEUR

2. Prestations 3D : deux calculs indépendants

2.1 Conception 3D intérieure

La prestation Conception 3D intérieure utilise uniquement la surface intérieure.

total3DInterior = surfaceInterior × rate3DInterior

2.2 Conception 3D extérieure

La prestation Conception 3D extérieure utilise uniquement la surface extérieure.

total3DExterior = surfaceExterior × rate3DExterior

2.3 Si les deux prestations sont sélectionnées

total3D = total3DInterior + total3DExterior
Ces deux prestations sont les prestations de référence par défaut pour les deux familles de surfaces : Intérieur → tarif 3D intérieur ; Extérieur → tarif 3D extérieur.

Exemple de référence

Données :

surfaceInterior = 100 m²
surfaceExterior = 50 m²
rate3DInterior = 900 DA/m²
rate3DExterior = 600 DA/m²
SélectionCalculTotal
3D intérieur uniquement100 × 90090 000 DA
3D extérieur uniquement50 × 60030 000 DA
3D intérieur + extérieur(100 × 900) + (50 × 600)120 000 DA
Référence arithmétique à utiliser par le développeur : avec 50 m² à 600 DA/m², le total extérieur est 30 000 DA. Le total combiné est donc 120 000 DA.
2D · SURFACE

3. Prestations 2D : choix Intérieur / Extérieur par prestation

Sont concernés notamment : plomberie, éclairage / luminaires, faux plafond, électricité, revêtement, démolition / construction et autres plans 2D facturés au m².

3.1 Comportement lors de la sélection d’une prestation 2D

  • La case Intérieur est cochée automatiquement par défaut si une surface intérieure existe.
  • La case Extérieur est affichée uniquement si l’Admin autorise cette prestation à être appliquée à l’extérieur.
  • Le client peut sélectionner Intérieur uniquement, Extérieur uniquement, ou les deux.
  • Chaque changement recalcule le prix immédiatement.
☑ Intérieur  100 m²
☐ Extérieur   50 m²

3.2 Formule

selected2DSurface =
  (useInterior ? surfaceInterior : 0)
+ (useExterior ? surfaceExterior : 0)

total2D = selected2DSurface × service2DRate

3.3 Exemple

Données :

surfaceInterior = 100 m²
surfaceExterior = 50 m²
service2DRate = 150 DA/m²
Cases cochéesSurface facturéeCalculTotal
Intérieur uniquement100 m²100 × 15015 000 DA

La même logique doit être réutilisée par toutes les prestations 2D configurées avec un prix au m². Ne pas recréer une formule différente pour chaque plan.
Configuration Admin

4. L’Admin contrôle si une prestation 2D peut être appliquée à l’extérieur

Chaque prestation 2D doit contenir au minimum les propriétés suivantes :

pricingType = PRICE_PER_M2

allowInterior = true / false
allowExterior = true / false

defaultInteriorSelected = true / false
defaultExteriorSelected = true / false

unitRate = number

Configuration recommandée pour la majorité des plans 2D :

allowInterior = true
allowExterior = true ou false selon la prestation
defaultInteriorSelected = true
defaultExteriorSelected = false

Règle d’affichage

if allowExterior == false:
    ne pas afficher la case "Extérieur"

if allowInterior == false:
    ne pas afficher la case "Intérieur"
Une option non autorisée par l’Admin ne doit pas seulement être cachée visuellement : l’API doit également refuser qu’elle soit utilisée dans le calcul.
HORAIRE

5. Prestations facturées à l’heure

Lorsqu’une prestation horaire est sélectionnée, afficher un champ de saisie du nombre d’heures.

Nombre d’heures : [ 20 ]

totalHourly = hours × hourlyRate

Exemple

hourlyRate = 5 000 DA/h
hours = 20

total = 20 × 5 000
total = 100 000 DA
  • Le nombre d’heures doit être supérieur à 0.
  • Le montant doit être recalculé en temps réel.
  • Le récapitulatif doit afficher : 20 h × 5 000 DA/h = 100 000 DA.
PRIX FIXE / QUANTITÉ

6. Prestations à prix fixe

Lorsqu’un service au prix fixe est sélectionné, afficher un champ Quantité.

Quantité : [ 3 ]

totalFixed = quantity × fixedUnitPrice

Exemple

fixedUnitPrice = 100 000 DA
quantity = 3

total = 3 × 100 000
total = 300 000 DA
Le libellé d’un prix fixe doit utiliser la bonne unité métier : « / façade », « / unité », « / visite », etc. — jamais « / m² » si ce n’est pas une prestation au m².
POURCENTAGE

7. Prestations calculées en pourcentage

Lorsqu’une prestation en pourcentage est sélectionnée, afficher un champ Montant de référence en DA. 

Montant de référence : [ 100 000 DA ]

totalPercentage = referenceAmount × percentage / 100

Exemple

referenceAmount = 100 000 DA
percentage = 10 %

total = 100 000 × 10 / 100
total = 10 000 DA
  • Le pourcentage est défini par l’Admin dans la prestation.
  • Le client saisit uniquement le montant de référence.
  • Le montant calculé est mis à jour instantanément.
  • Le récapitulatif doit afficher clairement la base : 10 % de 100 000 DA = 10 000 DA.
Cette spécification demande un champ de montant de référence au niveau de la prestation sélectionnée. Si l’implémentation actuelle utilise un unique « coût global du projet » partagé par toutes les prestations en pourcentage, elle doit être adaptée à cette nouvelle règle du Compositeur.

PSEUDO-CODE

11. Fonction de calcul unique

function calculateService(service, selection, project) {

  switch (service.pricingType) {

    case "PRICE_PER_M2":
      let selectedSurface = 0

      if (selection.useInterior)
        selectedSurface += project.surfaceInterior

      if (selection.useExterior)
        selectedSurface += project.surfaceExterior

      return selectedSurface * service.unitRate


    case "HOURLY":
      return selection.hours * service.hourlyRate


    case "FIXED_UNIT":
      return selection.quantity * service.fixedUnitPrice


    case "PERCENTAGE":
      return selection.referenceAmount
             * service.percentage / 100
  }
}

Le même moteur doit être utilisé pour :

Compositeur→ API→ Récapitulatif→ Devis→ PDF

INSTRUCTION DÉVELOPPEUR

13. Règles non négociables

  1. Une prestation 3D intérieure ne doit jamais utiliser la surface extérieure.
  2. Une prestation 3D extérieure ne doit jamais utiliser la surface intérieure.
  3. Une prestation 2D utilise uniquement les surfaces cochées sur cette prestation.
  4. La case Intérieur d’une prestation 2D est cochée par défaut lorsqu’elle est autorisée et qu’une surface intérieure existe.
  5. La disponibilité de la case Extérieur d’un plan 2D est administrable.
  6. Une prestation horaire utilise uniquement heures × prix horaire.
  7. Une prestation fixe utilise uniquement quantité × prix unitaire fixe.
  8. Une prestation en pourcentage utilise uniquement montant de référence × pourcentage.
  9. Le détail du calcul doit être sauvegardé avec le devis, pas seulement le total.
  10. Le Frontend ne doit contenir aucun tarif, pourcentage ou règle de disponibilité codé en dur si ces valeurs existent dans l’Admin.
Critère de réussite : un même jeu de données doit produire exactement le même résultat dans le Compositeur, le récapitulatif, le devis sauvegardé et le PDF final.
